# 写一节课

## 目录

```
课程/NN-课程名/
├── lesson.md      讲义（给孩子看的正文，≤600 字）
├── demo/          能直接跑的东西
├── takeaway.md    一句话结论，≤30 字
└── 家长话.md      给家长：讲了什么、卡在哪、怎么追问，≤200 字
```

## 六个必填项，缺一项就算没做完

| 项 | 要求 |
|---|---|
| 一个类比 | 从孩子身边的东西出发，一句话讲完 |
| 一个概念 | 这节课只引入一个新概念 |
| 一个可运行产物 | 双击能开，或 `python3` 能跑，零安装 |
| 「猜一猜」 | 动手前先预测，有悬念，一句话 |
| 「改一改」 | 只改一个参数，立刻看到变化 |
| 硬件动作 | 在真机屏幕上做出什么（附模拟器预览） |

代码量上限：单文件 ≤ 40 行。

## 写作规则

- 先给结果，再讲道理。孩子先看见星，再问为什么是 72°。
- 每段不超过 4 行。
- 不用"首先/其次/综上所述"。
- 不出现"很简单""聪明"这类评价。
- 抽象概念必须有实体对应：循环=折纸重复，变量=存钱罐，函数=动作打包。

## 验收

写完必须真的跑一遍：

```sh
cd 课程/NN-课程名/demo
python3 star.py            # 或双击 index.html
```

再跑一遍对比（涉及硬件的课）：

```sh
python3 tools/compare.py
```

讲义里出现的每条命令，都要在模拟器上真的产生预期图形。**没跑过的课不算写完。**

## 反例

2000 字、300 行代码、让孩子"理解面向对象"。这个契约就是用来防它的。
